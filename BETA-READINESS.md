# Kinkan: подготовка беты

База: tt.13 (21043a1), слита подготовленная ветка merge/mikan-0.5.1.0.
Перенос на Citrus и новые функции Mikan 0.5.1.1 выполняются после проверки этой базы.
Документ фиксирует результаты 17.10.2026; не является объявлением готового релиза.

## Проверено локально

- Слияние без конфликтов; сборка cmd/mikan и cmd/mikan-node.
- pnpm install --frozen-lockfile и production build: TypeScript, contrast, Vite.
- go vet ./....
- Тесты proto, release, ttprobe, nodeprobe, scannerlog, panel/updates, mikan-release.
- Race-тесты nodeapi, nodeprobe, ttprobe, scannerlog, panel/updates.
- Пакет node на Windows не зелёный: TestNodeSaysWhoHoldsPort80 (код ошибки bind),
  TestPutSiteChecksTheArchive (Unix-права 0600). На Linux пакет node прошёл с -race, в том числе после HPACK-исправления; проверки не отключались.
- Cargo.lock обновлён с rustls 0.23.45 до 0.23.46 точно по upstream 804960ebf.
  На Linux прошли fmt, clippy, 181 тест, locked build, test-upgrade.sh и test-install.sh. Cargo audit ещё ожидается.

## Проверки безопасности и Linux-стенд

- govulncheck v1.8.0 на Windows с Go 1.27.2: 0 уязвимостей в вызываемом коде.
  Две записи в зависимостях без найденных вызовов остаются в отчёте; это не аудит всего кода.
- Первый прогон на старом локальном Go 1.27.1 сообщил о 11 уязвимостях стандартной библиотеки.
  Повтор на 1.27.2 прошёл. Release Dockerfile уже закрепляет Go 1.27.2 с digest;
  go.mod также требует минимум 1.27.2: с GOTOOLCHAIN=local Go 1.27.1 отклонён, 1.27.2 принят. Старые локальные бинарники, собранные 1.27.1, для выпуска не использовать.
- На QWINS создан отдельный стенд /opt/kinkan-beta-lab-20261017:
  Docker-сеть, PostgreSQL 18 без опубликованных портов, отдельные исходники и кэши.
  Рабочая БД и конфигурация ноды не используются.
- Полный Linux vet/race, Rust fmt/clippy/test/build, installer fault-injection,
  cargo audit, Linux govulncheck и тесты изменённых вложенных модулей запущены/поставлены
  с ограничением ресурсов. Go и Rust частично выполняются параллельно; повтор Go и e2e ждут своей очереди. Результаты ожидаются; запуск не считается успешной проверкой.

## Ограничения первого Linux-прогона

Первый запуск с -race прерван после двух OOM (panel/app и panel/cli, подтверждено
memory.events: oom_kill=2) и таймаута всего billing-пакета в 240 с; последний его
тест шёл лишь 4 с. Это не зелёный прогон и не доказательство ошибки в этих пакетах.
Повтор выполняется на исправленных исходниках: GOMEMLIMIT=200MiB вместо 600MiB,
лимит контейнера 900MiB, один пакет за раз, timeout=600s.
Для одноразовой БД включён synchronous_commit=off при fsync=on, чтобы ускорить
многочисленные тестовые транзакции. Эти проверки не моделируют crash durability БД.
Рабочие контейнеры и их настройки не менялись. В повторе panel/app прошёл с -race за 570.512 с, без OOM; остальная часть прогона ещё не завершена.

## Исправление, найденное при проверке

В копии metacubex/http v0.1.8 оставалась гонка HPACK-кодировщика HTTP/2:
processSetting менял его из serve loop, пока writeFrameAsync мог кодировать HEADERS.
Это участок из GO-2026-6617; новая версия компилятора не обновляет скопированный код.
Перенесена логика Go 1.27.2: изменения SETTINGS_HEADER_TABLE_SIZE откладываются
до следующей записи кадра, с сохранением минимального и последнего размера.

- Патч: patches/metacubex-http/0002-hpack-encoder-ownership.patch.
- TestKinkanHeaderTableSizeDuringWrite на старом коде падает: 2048 вместо 4096
  во время активной записи; с исправлением TestKinkan* проходит -race -count=20 на Windows.
- Linux-проверка воспроизводимости патча, тесты ядра и ноды с исправлением ещё ожидаются.
- Полный исходный Linux-прогон начался до этой правки; его результат отдельно от
  последующих проверок исправленного HTTP-форка.

## Регрессия обновления с tt.13

Добавлен TestUpgradeFromTT13PreservesData. Он создаёт старую схему PostgreSQL
(миграции 1..15, файлы совпадают с v0.5.0.5-tt.13) с данными пользователей,
ключами подписки, счётчиками, устройством, TT fallback, сайтом и scanner row.
После текущих миграций проверяет сохранность этих данных, новые значения по
умолчанию и однократный перенос старого unbound_at в историю отвязок.
Это проверка SQL-миграций; она не заменяет обновление опубликованного образа,
проверку HTTP-подписки и откат с восстановлением бэкапа. Linux-результат ожидается.
