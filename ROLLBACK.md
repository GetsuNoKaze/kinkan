# Откат версии из панели

В **Настройках → Обновления** можно вернуть версию, которая работала перед
последним успешным обновлением. Откат сохраняет текущую базу: новые пользователи,
платежи и настройки остаются. Это одна точка возврата, без выбора произвольного
старого релиза и без восстановления базы из снимка.

Кнопка появляется, если обновление не меняло схему PostgreSQL Mikan, а при
возврате к Kinkan — ещё и схему Kinkan. Предыдущий Docker-образ должен сохраниться
на сервере. Старый Mikan не читает таблицы Kinkan. Неизвестный результат
миграции тоже запрещает откат. Переход с SQLite на PostgreSQL откатывать этой
кнопкой нельзя. В панели будет написано, почему откат недоступен.

## Что происходит после подтверждения

1. Панель отключает автообновление в настройках и в политике сервера, затем
   отправляет запрос. Откат доступен только через сессию администратора с CSRF;
   API-ключом его запустить нельзя.
2. Установщик берёт общую блокировку операций сервера и проверяет, что текущая
   версия и точка возврата всё ещё совпадают с запросом. Образ он берёт из своей
   записи, а не из запроса панели. Перед остановкой проверяет его версию.
3. Создаёт резервную копию. После остановки панели делает ещё одну копию,
   включающую последние принятые записи. Если копирование не удалось, образ
   не меняется и сервер пытается снова запустить текущую панель.
4. Запускает прежний образ на текущих данных и проверяет готовность. Миграции
   вниз и автоматического восстановления базы нет.
5. Если прежняя версия не запустилась, пытается вернуть текущую. Если не
   запускаются обе, останавливает панель, сохраняет данные и пишет ошибку с путём
   резервной копии в статус обновления.

Панель ненадолго отключится. После перезапуска обнови страницу. Автообновление
останется выключенным; включить его обратно можно вручную.

Панель и встроенная нода используют один Docker-образ, поэтому встроенная нода
тоже перезапустится на прежней версии. **Удалённые ноды не откатываются**:
механизм следования за панелью обновляет только отстающие ноды.

## Точка возврата

Точку записывает установщик с поддержкой этой функции после успешного обновления.
Одна только новая панель поверх старого установщика не создаёт её задним числом.
После отката точка помечается использованной. Следующее успешное обновление
создаст новую; отката по цепочке к ещё более старым версиям нет.

Сервер хранит разрешённый образ по неизменяемому Docker image ID, взятому из
прежнего контейнера. Переназначение тега не меняет цель отката. Запись находится
в `/opt/mikan/kinkan-rollback.json`, вне каталогов данных контейнеров, доступна
только root. Панель видит описание без образа в
`/opt/mikan/data/panel/update/rollback.json`.

Не чисти образы Docker, пока нужен откат: после обновления предыдущий образ
остаётся без тега, и его удаляет любая чистка — `docker image prune` (даже
без `-a`) и `docker system prune`.
Если образ удалён после записи точки, сервер откажется **до остановки панели**.
Повторное нажатие и одновременный запрос обновления не перезаписывают друг друга.

## API

- `GET /api/v1/updates/rollback` — текущая и предыдущая версии, доступность,
  причина отказа и время записи точки; требуется авторизация.
- `POST /api/v1/updates/rollback/request` с `{"version":"<предыдущая версия>"}` —
  запрос на откат; требуется сессия администратора и CSRF. Ответ `202` означает,
  что заявка принята, а не что откат завершился.
- Состояние операции и ошибка — существующий `host` в `GET /api/v1/updates`.

## Проверки разработки

`scripts/tt/check.sh` включает тесты очереди обновления и отката без базы.
Тесты API проверяют сессию, CSRF, запрет API-ключа, произвольного релиза и повторной
заявки, а также отключение автообновления; им нужна одноразовая PostgreSQL через
`MIKAN_TEST_DATABASE_URL`. `cargo test` в `installer/` проверяет разрешённый
образ, смену версии, схему и безопасную публикацию записи панели.

Перед выпуском нужен прогон обновления и отката на Docker-стенде, включая отказ
резервного копирования и нездоровый прежний образ. Эти сценарии не подтверждаются
одними тестами разбора запросов и схемы.
