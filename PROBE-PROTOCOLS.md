# Проверка протоколов и журнал обращений

В панели: **Ноды → Проверка протоколов**. Можно выбрать одно подключение или все
включённые inbound'ы. HTTPS-порт сайта для сравнения задаётся отдельно. Запросы идут
с панели, DNS проверяется один раз, все TCP и UDP подключения закреплены за публичным
IP ноды. Клиентские адреса и REALITY dest не сканируются. Доступ — админская сессия
с CSRF; одновременно работает одна проверка, весь прогон ограничен 240 секундами,
одно подключение — 2 секундами, один inbound — 75 секундами.

CLI сохраняет старый формат TrustTunnel по умолчанию ([PROBE-TT.md](PROBE-TT.md)):

```sh
kinkan probe --protocol anytls --reference https://node.example:8444 https://node.example:2083
kinkan probe --protocol tuic --json https://node.example:8443
kinkan probe --protocol hysteria2 --obfuscated --json https://node.example:443
```

Для отчёта сразу по нескольким подключениям передайте JSON-файл **без паролей**:

```json
[
  {"protocol":"vless","target":"https://node.example:443","reference":"https://node.example:8444","address":"203.0.113.10"},
  {"protocol":"tuic","target":"https://node.example:8443","address":"203.0.113.10","alpn":["h3"]},
  {"protocol":"shadowsocks","target":"https://node.example:2443","address":"203.0.113.10"}
]
```

```sh
kinkan probe --inbounds inbounds.json --timeout 3s --json > probe.json
```

Адрес `https://` в таком файле задаёт имя TLS/Host и порт, **не** означает, что
Shadowsocks использует HTTPS. `address` закрепляет и цель, и эталон за одним IP;
для REALITY имя в `target` должно совпадать с SNI сайта-прикрытия. Сертификаты
проверяются системными корнями. В отличие от API, CLI допускает локальные адреса
для стенда. Файл содержит 1–64 подключения. Диапазоны портов в панели показываются
как неподдержанный замер; для каждого порта можно задать отдельную строку CLI.

## Что измеряется

- VLESS, VMess, Trojan, AnyTLS и TrustTunnel: существующие проверки TLS/SNI/ALPN,
  сертификата, HTTP/1, HTTP/2, авторизации прокси и отпечатка HTTP/2; дополнительно
  реакция на случайные данные 32, 256 и 1024 байта. Сравнение реакции с сайтом
  оценивает тип ответа и строку статуса, время выводится отдельно.
- Hysteria2, TUIC и ShadowQUIC: QUIC с `h3` и дополнительно настроенным ALPN,
  сертификат, закрытие соединения без авторизации, HTTP/3 GET и POST `/auth` с
  неверным Hysteria-Auth; у TUIC — неверный AUTH v5. Для HTTP/3 сравнения эталон
  должен отвечать по UDP на указанном порту. Коды TUIC `0xfffffff1` и `0xfffffff2`
  определяются только при **удалённом** закрытии, локальные ошибки не считаются утечкой.
- Shadowsocks, Snell, Sudoku и Mieru: случайные байты через TCP, количество ответа,
  закрытие или таймаут, длительность. UDP-варианты этих транспортов пока не измеряются.

Вердикты: `quiet` — выполненные пробы совпали с эталоном; `noticeable` — наблюдались
отличия; `exposed` — явный признак протокола/прокси; `inconclusive` — данных недостаточно.
`incomplete` сохраняется отдельно даже при явной утечке. Отсутствие ответа при obfs,
ошибки сети и измерение времени сами по себе не дают вердикт «тихий».
CLI возвращает 1 при утечке или неполном замере, 0 при завершённом замере без утечки;
отличия `noticeable` требуют оценки администратора. Пробы не выключают протоколы.

## Журнал

**Ноды → Журнал сканеров** показывает агрегаты по IP/inbound, ASN, организацию,
страну и обратный DNS, тип запроса, число попыток и первое/последнее время. График
содержит 30 дней по UTC. Всплеск — от 100 посторонних обращений за сегодня и более
трёх среднесуточных значений за предыдущие семь дней.

Первые точки сбора в патче `0002-auth-events.patch`:

| Протокол | Событие |
|---|---|
| TrustTunnel | HTTP без авторизации или с неверной авторизацией |
| REALITY | Рукопожатие, которое не вернуло авторизованное соединение |
| TUIC v4/v5 | Таймаут или отказ авторизации, один раз на решение авторизации |
| Hysteria2 | Отклонённый POST на `hysteria/auth` |
| AnyTLS | Неверный хеш пароля |

**Это ещё не полный журнал всех протоколов.** Обычные HTTP-запросы Hysteria2,
ошибки до завершения QUIC/obfs, неполные заголовки AnyTLS, авторизация VLESS/VMess/
Trojan после успешного REALITY и шумовые протоколы пока не имеют отдельных точек.
На официальном Mikan новых событий нет; прошлые обращения восстановить нельзя.

Хранятся только метаданные отказов, без пароля, URL, query, заголовков и трафика
успешных пользователей. События без авторизации могут быть обычными браузерами:
неизвестный источник не объявляется доказанным сканером. Адрес, использованный
авторизованным клиентом в последний час или известный с другой ноды, помечается
«вероятно, свой клиент» и по умолчанию скрыт из таблицы и статистики всплесков.

Нода держит до 10 000 агрегатов, очередь событий — 1024, очередь обогащения — 128.
Метаданные обогащаются в отдельном потоке, не задерживая рукопожатие. Новые записи
сверх лимита отбрасываются; счётчики существующих источников продолжают расти.
Срок — 30 календарных дней UTC. Снимок сохраняется атомарно с правами 0600,
периодически и перед передачей панели; повторная доставка не удваивает числа.
Панель опрашивает журнал раз в 30 секунд, хранит максимум 10 000 строк на ноду,
удаляет истёкшие записи в общем обслуживании базы, в том числе для отключённых нод.
Миграция находится отдельно в `store/kinkan`, версия апстрима не меняется.

GeoIP/ASN читаются из существующих локальных MMDB ядра: отсутствие базы оставляет
поле пустым, не скачивает данные и не прерывает работу VPN. PTR подтверждается
прямым DNS-разрешением в исходный IP; суффиксы доменов сверяются по границам меток.
Атрибуция Censys также использует [опубликованные сети](https://docs.censys.com/docs/opt-out-of-data-collection)
(срез 10.10.2026). Для Shodan, Rapid7 и BinaryEdge применяется подсказка по
подтверждённому PTR; полного списка их сетей здесь пока нет. Атрибуция не используется
как основание для блокировки.

## Проверка 10.10.2026

- QWINS на tt.5, проверка TUIC с самого стенда: `AuthenticationTimeout`
  `0xfffffff2` через примерно 1.1 с и `AuthenticationFailed` `0xfffffff1` при неверном AUTH.
- Изолированная новая нода на временных loopback-портах: события получены от всех
  пяти точек сбора, временные процесс, сертификат и данные удалены после проверки.
- С неправильным SNI сертификата стенда результат — незавершённый замер,
  а не «тихий»: сертификат стенда выписан на его имя sslip.io.
